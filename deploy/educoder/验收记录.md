## 多账号闭环与恢复

在 `dsh-2c8g` 安装 `@forst/dsh-educoder 0.1.0`，加载专用凭据边界，使用真实 DSH Web、Session 和 Pi 适配器对接 EduCoder 与模型替身。API 验收显示两个账号各自发现课程和作业，错误账号分配整批拒绝，实际并发为 2。两个账号分别保存一次、评测一次，各观察到三次远端通过状态。重复分配沿用原任务，登录过期及重新登录只影响对应账号。API 用例的 Session 为 `b83e3408-598d-4ffb-a5fd-78f232be1e4f` 与 `d3252c54-109c-436c-a5f8-26255f0a9a59`。

服务器 Chromium 用原生侧边栏打开 EduCoder 面板，选择各自作业、批量启动、检查核验结果和打开关联 Session。刷新未触发额外写入。测试耗时约 10 秒，未捕获页面异常或凭据回显。宿主文件读取、文件上传、目录选择、手动创建和控制会话、命令执行与预设切换均由服务端拒绝。会话历史和模型目录保持可读取。

调度恢复测试模拟提交响应丢失、超时及进程强制退出。恢复后先查询已提交关卡，过期的失败标记不能触发再提交。多文件和终端在模拟传输中分别完成评测。真实终端执行器需要单独配置和验收。图形题、选择题和无法确认作业范围的题型暂停，等待人工处理。

本地运行 `node tests/educoder-soak.mjs --duration-ms 120000`。8 个模拟账号共 809 项任务通过，记录 809 次提交、2,099 次成功读回、159 次模拟响应丢失和 3 次在途重启，无重复提交。峰值并发 3，RSS 从约 49 MiB 上升到峰值 222 MiB，结束约 202 MiB。当前存储每次写入会保存队列快照，大量历史任务会增加资源使用。本轮为工作流及调度器稳定性测试。真实 DSH 桌面与浏览器的长期稳定性尚待验收。

## 真实 OpenCode Go 与模拟 EduCoder 联调

同日，另启专用容器和一次性卷进行真实模型联调。测试输入来自一个模拟账号的 Python 单文件关卡，模型经过本机回环转发请求 OpenCode Go 的 `deepseek-v4.1-flash`。转发仅接受这个关卡的三项工具，检查凭据标记，限制最多五个请求和每次 1024 个输出 token。真实 Go 密钥仅由转发进程以只读方式访问，DSH 使用模拟转发令牌。

| 项目 | 实测结果 |
| --- | --- |
| 会话 | 临时 DSH Session `438a186f-9182-4d83-b6a7-956b483ad1fd`。任务在一次尝试内标记通过 |
| 工具范围 | 四次模型请求的工具声明均恰好包含 `educoder_read_file`、`educoder_save_file` 和 `educoder_evaluate`。转发未发现模拟密码、Cookie、签名材料或隐藏测试输出进入请求 |
| 远端核验 | 替身记录一次读取、一次保存、一次评测和三次通过状态回读。无越界访问 |
| Web 边界 | 已认证请求访问宿主文件读取路径和 Session 上传路径时均返回 403 |
| Go 兼容性 | 直接转发原 DSH/Pi 请求返回 HTTP 400，提示缺少 `x-opencode-session`。为本次对话补充稳定会话标识和独立 User-Agent 后，四次流式请求均返回 HTTP 200。联调采用 `thinking.type=disabled` |

本次模型转发只服务于隔离验收。独立部署直接使用当前 DSH/Pi 版本对接 Go 时，仍需由受信任的模型适配层为每个会话发送稳定标识。EduCoder 平台端由替身提供，未操作真实账号或作业。
